# ADR 0029: Mapped compiler lookups with snapshot leases

- Status: Accepted
- Date: 2026-09-30
- Predecessors: [ADR 0028](./0028-semantic-snapshot-attachments.md),
  [ADR 0025](./0025-mmap-bm25-and-dense-sidecars.md)

## Decision

Build a compact compiler lookup index alongside each newly attached semantic
artifact. Keep the original artifact for audit; serving maps a separate binary
representation containing the records and lookup tables needed for source-context
discovery, exact-position bindings, and qualified-symbol definitions.

This implements navigation over recorded compiler evidence. It does not infer
runtime dispatch, build a new CALLS graph, change syntax-graph confidence, or
automatically enrich ranked search results. ADR 0028's historical-input and
freshness limits remain in force.

## Persistence

`internal/semanticindex` uses a versioned fixed header, interned UTF-8 strings,
fixed-width record tables, candidate lists, source/context memberships, and sorted
position and definition postings. It uses the existing `mmapslice` mapping
implementation without introducing new unsafe code. Build validates a complete
artifact and writes an independent immutable file. Open validates bounds,
provenance, payload integrity, foreign keys, spans and posting order before queries
can access mapped bytes.

The binary header records the source audit artifact's SHA256 and the snapshot
manifest's corpus fingerprint. A separate `semantic_index` component names
`semantic/index.msi`, requires the audit component, and repeats both bindings in
its descriptor. Snapshot resolution verifies the advertised files' integrity.
The builder opens and validates the derived index before committing the generation.
Old audit-only snapshots remain readable but offer no compiler lookup index.

The index is limited to 128 MiB in this first format. Warm opening does not decode
the audit JSON, embedded generated bytes, diagnostic objects or build-capture
manifests into the serving heap. Those remain in the audit artifact. Per-query
results are bounded and own their strings and slices, so serializing a response
after releasing the lease cannot access retired mappings. This format limit is
not a measured corpus-scale capacity claim or an exact process RSS bound.

## Query contract

`compiler_binding_at` accepts an exact token-start offset in **raw UTF-8 bytes**,
including any BOM. It does not accept search-normalized offsets or a cursor
anywhere inside a token. Repository and path identify a source occurrence rather
than a content blob shared by several projects.

Without a selected context, the tool returns bounded context choices with their
raw source hashes. Selecting a context requires its hash. It preserves every
matching same-token occurrence, including overlapping type and constructor facts,
with explicit resolved/ambiguous/unresolved/unsupported status. Candidate symbols
remain alternatives. Missing coverage, missing context, source mismatch and an
empty position are distinct from a compiler-observed unresolved binding.

`compiler_definitions` accepts a qualified symbol ID and optional repository and
context filters. It returns only resolved declaration occurrences, preserving
partial declarations and context variants. External symbols may have no recorded
definition. Generated sources retain their generated flag and captured path;
no checkout path or executable runtime edge is invented.

Both tools identify their snapshot and audit artifact and report recorded compiler
context evidence. Responses are non-cacheable until a semantic cache identity
contract is implemented. Filters apply before result limits; truncation is explicit.
No compiler tools claim fresh project evaluation or complete language coverage.

## Lifetime and reload

MCP boot and reload retain one explicit `snapshot.Resolved` value through source,
graph and compiler preparation. The compiler mapping joins the existing immutable
serving holder and is retired only after all readers release their leases.
Preparation failure leaves the old holder active. A valid semantic-free replacement
reports compiler evidence unavailable; it never carries old semantic data forward.

The tool catalog is stable across reloads. An absent index returns explicit
unavailability rather than hiding a tool at boot. Explicit legacy shard-directory
access never discovers a neighboring semantic file. Compiler result ownership is
necessary because MCP serializes returned maps after tool-call lease release.

## Next gates

Measure real-project file sizes, opening cost and query latency; expand independent
compiler labels and language coverage; normalize package identities; implement
managed compiler execution and clean/incremental equivalence. Search annotation,
cross-service adapters, impact queries and paired CodeGraph task evaluation remain
separate acceptance gates.
