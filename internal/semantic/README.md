# Offline semantic artifact

See [ADR 0027](../../docs/adr/0027-compiler-worker-and-semantic-artifact.md) for the
identity, raw-byte, completeness and publication boundaries. This is a bounded
staging format; it is not automatically loaded by serving.

After capturing a restored project with the [worker](../../tools/semantic-dotnet/README.md):

```sh
moedex semantic import \
  --input /scratch/capture.jsonl --root /scratch/projection \
  --repo group/project --output /scratch/semantic-v1.json
moedex semantic inspect /scratch/semantic-v1.json
```

The output file must not already exist. Incomplete/malformed captures create no
staged artifact. The ordinary source/configuration files in `--root` must still
match the capture; genuinely virtual generated sources are embedded. Known
acquisition metadata can be supplied with `--project-id` and `--commit`; leave it
absent when unknown. Those options are caller assertions, not Git verification.

The commands emit a JSON summary and never change an active `CURRENT` pointer.
To attach one complete artifact to a newly built snapshot explicitly:

```sh
moedex index snapshot build -corpus /scratch/corpus -index-dir /scratch/index \
  -semantic-artifact /scratch/semantic-v1.json
```

The repository namespace must match the discovered corpus repository. Recorded
source and local build inputs must still exist there with matching bytes; ordinary
sources and project files must also belong to the new lexical index. Whole-workspace
privacy eligibility is required for generated content and diagnostics. A failed
attachment preserves `CURRENT`; omitting the flag on the next build drops the
attachment. Snapshot resolution checks the attachment's bounded file integrity.
The artifact remains audit evidence. New builds also produce a compact mapped
index for [recorded compiler lookups](../semanticindex/README.md). See
[ADR 0028](../../docs/adr/0028-semantic-snapshot-attachments.md) for the recorded-input
freshness limits and publication contract.

`Read` and `Write` use a 64 MiB encoded-file bound. Record validation includes
content IDs, memberships, dependency completion, binding/diagnostic targets and
span bounds. Import validates raw source bytes through a confined filesystem root.
Generated bytes are stored and revalidated. Checksums detect corruption, not a
maliciously rewritten but internally consistent capture.

`go test ./internal/semantic ./internal/semanticimport ./internal/eval` runs the
hermetic tests. The actual worker-output round trip is enabled with
`MOEDEX_SEMANTIC_WORKER_OUTPUT` and `MOEDEX_SEMANTIC_WORKER_ROOT`; the maintained
worker suite's `Both.jsonl` capture contains both linked-source contexts.

The worker suite also produces `Generated.jsonl` and `ThrowApp.jsonl`. Set
`MOEDEX_SEMANTIC_GENERATED_OUTPUT` and `MOEDEX_SEMANTIC_THROWING_OUTPUT` alongside
the same root to exercise generated-byte round trips and failed-generator staging
rejection through the real importer.


## Compose separate captures

```sh
moedex semantic compose --input /scratch/publisher.semantic \
  --input /scratch/consumer.semantic --output /scratch/composed.semantic
```

Inputs must be complete validated artifacts. Up to 32 inputs share a 64 MiB
aggregate encoded-input budget; the output has the same bound. `--max-bytes` can
lower it. Exact repeated records deduplicate; contradictory records or bindings
fail. Output order is deterministic and build variants remain distinct. The JSON
summary lists source snapshot IDs, repository/project details, and contributing
input files. Composition verifies recorded integrity; it does not reread source
workspaces or assert that independently captured projects are deployment-compatible.

For separate retained projections, create a local JSON map using the source
snapshot IDs from that summary:

```json
{
  "snapshot:<publisher digest>": "/scratch/publisher-workspace/source",
  "snapshot:<consumer digest>": "/scratch/consumer-workspace/source"
}
```

```sh
moedex index snapshot build --corpus /scratch/corpus --index-dir /scratch/index \
  --semantic-artifact /scratch/composed.semantic \
  --semantic-workspaces /scratch/workspaces.json
```

The map must cover every artifact snapshot exactly once. Relative roots resolve
beside the map file. It is mutually exclusive with `--semantic-workspace`, which
continues to support a single snapshot. Without either option, publication checks
recorded inputs in the corresponding corpus directories. Every projection must
pass privacy and retained-input checks, while captured sources must match the
indexed corpus. An alternative revision/configuration may compose successfully
but fail publication if its source/configuration conflicts with that generation.
Failures preserve CURRENT. See [ADR 0039](../../docs/adr/0039-compiler-capture-composition.md).
