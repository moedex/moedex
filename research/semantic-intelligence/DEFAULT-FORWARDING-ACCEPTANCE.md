# Default-interface forwarding acceptance

Date: 2026-10-01. Worker9, single-threaded and CPU-only. This is a development
successor on known source, not a fresh holdout or independent-agent evaluation.

Moedex now automatically connects each selected eShop default to its closed generic
interface target and concrete handler implementation. It returns the qualified
cast type and exact captured call-site witness. The earlier selection/template
facts remain distinct; the cast is an explicit obligation, not an execution claim.

Each walkthrough starts with source search and bounded compiler declaration
discovery. It consumes the returned forwarding target, resolves that implementation,
checks the existing class correspondence, and verifies the qualified cast type.
Reverse discovery selects the handler context explicitly. Template lookup uses
the forwarding witness's recorded context; the call locator is passed directly
to `compiler_binding_at`. Source/BOM hashing independently checks the returned
offset, enclosing template and original interface-call identity.

All compiler responses within a case share one snapshot/artifact identity. Final
totals are 27 calls and 169,433 response bytes across three **separate**
24-call/131,072-byte budgets. Catalog retrieval is retained separately and uncharged.
Different call counts include same-basename search candidates without captured
compiler evidence. These are source-authored regression workflows, not independent
solvers or a before/after efficiency experiment.

## Scope and integrity

The optional `forwarding` object uses `csharp-default-forward-v1`. It represents
one supported source computation on `this`, with one explicit parameter cast,
closed target and concrete source implementation. It includes raw source hash,
path, UTF8 span, occurrence ID, source ID and context ID for the captured call.
Import and artifact validation check the actual binding and context dependency
closure; mapped-index open independently checks the stored witness. The index
layout remains v5, with additional symbols and JSON counted in existing budgets.

Conditional bodies, other receivers, extra computations/calls/arguments, `as`,
nested casts, async bodies and generic calls remain selection-only. Calls through
an inherited interface container and inherited class implementations also remain
outside this rule, even where selection is known. Cast success, runtime receiver
identity, DI activation, broker routing and execution remain unproved.

The ordinary `compiler_contract_paths` implementation-hop model is unchanged.
The new computation is exposed through existing compiler evidence tools; it is
not silently promoted into recursive or multi-step runtime flow.
See [ADR 0049](../../docs/adr/0049-bounded-default-interface-forwarding.md).
