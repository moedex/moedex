## Product boundaries

The first release serves three agent journeys: locate behavior, explain an actual
cross-service flow, and assess a contract change with source evidence. Memory,
operational-provider integrations, reviews, and a dashboard are subsequent product
increments. Documentation retrieval and architecture summaries enter when they
improve those journeys. No deployed-service changes or production reindex is implied
by a locally passing implementation gate.

## Delivery rules

- Source fixtures exercise extraction, persistence, and production tool handlers.
  Hand-built graph tests remain useful traversal tests but do not measure extraction.
- Confidence describes the evidence available for the target binding. A syntax match
  alone cannot promote a name-bound target to Verified or Proven.
- Content sharing must not collapse distinct repository/build-context meanings.
- Successful graph-enriched context must not combine different corpus snapshots.
- Unsupported analysis, ambiguity, stale data, and unavailable dependencies are
  distinct outcomes. Preserve diagnostic candidates without presenting them as facts.
- Exact lexical search retains its independent parity contract.
- A completed stage requires code, behavior tests, integration checks, and recorded
  evidence. Compiler availability, mocked results, and benchmark schemas alone do
  not demonstrate semantic quality or competitor superiority.

## Architecture contracts

### Identity and evidence

Keep the existing blob SHA as content identity. Introduce qualified symbol identity
(language, package/version, qualified descriptor/signature) and source occurrence
(repository, commit, relative path, span, build configuration) as distinct concepts.
Syntax caches can remain blob-addressed. Resolved facts must account for dependency
bindings, compiler configuration, and extractor/rule versions.

Extend evidence with the extractor/version, resolution method and status, immutable
source occurrence, and supporting spans. Represent service destinations, routes,
message contracts, queues, tables, packages, and jobs explicitly as domain adapters
are delivered. A route shape match and a configured destination are different facts.

Coordinate this work with ADR 0020 and the existing branch program. Do not introduce
a competing branch/provenance format. Default-branch semantics remain the default;
full multi-branch acquisition follows its existing prerequisite gates.

### Extraction

Use external, bounded compiler adapters with normalized output. C#/Roslyn is first,
TypeScript/Angular second, SQL and framework/configuration adapters next. Compare a
SCIP importer with direct compiler output on representative projects before choosing
the symbol ingestion strategy. Domain adapters remain necessary for messaging,
configured HTTP, ORM mappings, templates, and scheduled jobs.

Language servers continue to provide live navigation and targeted verification.
Compiler failure must leave lexical retrieval available and report semantic coverage
accurately. Run analyzers in writable projections of locked source, preserving the
managed-corpus isolation contract.

### Serving

Target one refcounted serving snapshot containing manifest, ranker, graph, and dense
artifacts, acquired once per request. Until that holder is implemented, independently
acquired incompatible fingerprints must produce a bounded, explicit non-cacheable
failure for graph-enriched context. Graph-disabled search remains available.

Task retrieval becomes scoped seed retrieval, resolved-root selection, bounded typed
graph expansion, evidence ranking, then context assembly. Bound visited nodes,
edges, wall time and delivered context. Publish forward and reverse adjacency when
the traversal performance slice lands. Preserve actual root-to-result paths.

### Freshness

Incremental output must equal a clean rebuild for additions, deletions, renames,
changed dependency bindings, configuration-only changes, and extractor upgrades.
Changing repository/path occurrences for unchanged bytes can change semantics and
must invalidate affected facts. New artifacts publish only after validation; old
readers remain usable until their references expire.

## First vertical slice

Select a representative shared-contract package, publishing service, consuming
service, storage mapping, and frontend at pinned commits. The release question is:

> If this contract changes, which applications are affected, through what paths,
> and which source and tests support that conclusion?

Use independently reviewed labels and explicit alternatives/unanswerable cases.
Begin with 30 varied paired tasks and reserve held-out repositories. Measure task
correctness, evidence precision/completeness, ambiguity handling, returned context,
tool calls, warm/cold latency, indexing resources and freshness. Stratify by language
and relationship family. Run both products against identical source identities and
record versions/configuration; results from different snapshots are not comparable.

Use a large public .NET repository as a separate scale and integration gate, at
one recorded commit with a pinned SDK, framework/configuration and project set.
The selected public repository is `dotnet/roslyn`, provisioned at detached commit
`36d26c5466e4d25940657ccb8d5b9557ccaf7be1`: 35,115 tracked files and
456,238,809 bytes of tracked content. The [public-corpus evidence](../../../research/semantic-intelligence/PUBLIC-CORPUS-ORACLE.md)
records the tree identity, source inventory and build constraints. Baseline lexical
parity and the file-boundary sharding correction both passed all 1,052 queries
against ripgrep and independent Go gold, with seed `20260930`, four scan workers
and two ripgrep workers. Both runs used identical query batteries and file scope;
all per-query match counts agree, with zero mismatches, quirks, or oracle errors.
Zoekt comparison is not enabled, and 34,791 eligible files fall below the separate
40,000-file scale target. The first named Roslyn compiler project now passes
production offline capture using the pinned SDK and a verified ten-package bundle,
with all ten frozen binding cases passing artifact and executable MCP checks
against a full lexical/ranking snapshot built with explicit `--graph=false`. Broader project and
semantic coverage remain pending. A selected-project capture must not be reported
as whole-repository compiler coverage.

The public Git adapter is implemented with explicit commit/origin and bounded
exact-source projection; it passed capture, frozen labels, unmanaged attachment,
and executable MCP on the original CodeGraph source fixture. Roslyn's first
compiler project and dependency requirements are recorded in
[compiler acceptance](../../../research/semantic-intelligence/ROSLYN-COMPILER-ACCEPTANCE.md).

Keep four kinds of evidence separate:

- **Source-authored semantic labels:** freeze expected targets, declaration
  anchors, alternative/unresolved cases and context distinctions before reading
  candidate output. Review representative overloads, generics, interfaces,
  partial and generated declarations, linked files, and configuration changes.
  Never generate the gold file from Moedex's returned bindings.
- **Compiler cross-checks:** use an independent harness over the same evaluated
  build inputs to inspect selected bindings and diagnostics. This can detect
  extraction/import errors, but using the same compiler is not independent proof
  of compiler correctness. Successful compilation alone does not verify every
  stored occurrence or tool response.
- **Text parity:** retain ripgrep/source-byte checks for retrieval, source
  membership and exact spans. Matching text does not establish semantic binding.
- **Resource measurements:** record projection/restore/capture/import/index
  timings separately, peak process RSS, artifact sizes, mapped-open allocations,
  query latency and timeout/output-limit failures. Fast execution does not imply
  correctness; report these alongside the frozen semantic results.

Record excluded projects and incomplete contexts, including missing packages,
unsupported targets and generator failures. Preserve explicit failure cases
rather than removing them from the denominator. Run all compiler-backed tool
checks against the captured commit and artifact identities. Any later CodeGraph
comparison must use the same source/build selection and separately authored task
labels; repository size or an internal oracle pass is not a competitive win.

## Measured graph-scale follow-up

The earlier expanded-storage graph-scale gate failed; preparation was no longer the measured
blocker. C# literal masking removes false definitions from quoted test programs;
source-first verification, bounded mask reuse, and a single identifier scan avoid
repeated per-pair and per-name work. The final Roslyn run scanned content in
3.194 seconds and prepared all 164,310 names in 19.009 seconds, including that
scan. It verified 8,898,523 sources and counted 232,754,358 non-self candidate
pairs. `Create` was the largest name: 25,559 sources, 852 definitions, and a
21,776,268 pair upper bound.

Expansion completed between the 18:01:24 and 18:01:45 log entries, producing
182,597,653 retained edges before deduplication. The run was stopped after
184.358 seconds when native sampling showed a 66.8 GB physical footprint while
aggregation copied the entire batch population into a second set of arrays.
No persisted full-corpus graph passed acceptance. Prior preparation observations
were 350.393 seconds after count/using fixes and 123.621 seconds with mask reuse;
post-run logs show those trials also reached expansion. Buffered harness output
had led to incorrect live phase assessments. These observations are not a
controlled benchmark comparison.

That failure motivated a pre-expansion resource census and a compact graph
candidate representation preserving confidence, evidence, and ambiguity.
Deleting the aggregation copy alone is insufficient: expanded batches already
occupy substantial memory, and the deduplication map and graph builder add
further per-edge storage. Further preparation tuning was not the critical
path. See the [historical graph acceptance record](../../../research/semantic-intelligence/ROSLYN-GRAPH-ACCEPTANCE.md)
and [measured result](../../../research/semantic-intelligence/results/roslyn-graph-20260930/result.json).
The selected-project compiler gate remains separately accepted at 10/10 frozen
cases through MCP, using explicit graph omission; it is not a syntax-graph pass.
